## 一、为什么要先改 schema 再重跑

Task 09 用 v1 schema 跑完 223 条，暴露了三个结构性缺陷：

| 缺陷 | 证据 |
|---|---|
| `topic` 无法聚合 | 192 条有主题，**前 20 高频的频次全是 1** |
| 情绪枚举不够用 | **`other` 出现 87 次**，排第二 |
| `interpretation` 会漏 | **2 条记录该字段完全缺失** |

**先重跑再改 schema，等于把同一批缺陷再跑一遍。** 所以 P0 是改 schema，不是花钱。

## 二、P0-A：topic 拆成 category + detail

### 2.1 新结构

```json
"topic": {
  "category": "body|mood|self|desire|relationship|work_money|daily|media|creation|society|knowledge|dream|unknown",
  "secondary": ["...≤2"],
  "detail": "自由描述，≤40 字",
  "basis": "explicit_in_text|inferred_from_text|unknown"
}
```

**分工**：`category` 用于统计聚合，`detail` 用于保留单条信息。**两者都要，缺一个都不行。**

### 2.2 12 个类别的定义

| category | 覆盖什么 | 典型主题 |
|---|---|---|
| `body` | 身体与生理 | 不适、困倦、疼痛、饥饿、生病、睡眠 |
| `mood` | 情绪与心理状态 | 低落、焦虑、恐惧、压抑、孤独 |
| `self` | 自我评价与改变 | 自责、能力评价、想变强、反思、人生 |
| `desire` | 欲望与渴望 | 对角色/人的喜爱、性、想吃 |
| `relationship` | 人际关系 | 家人、同事、朋友、信任、拉黑 |
| `work_money` | 工作与经济 | 求职、收入、省钱、贷款、兼职 |
| `daily` | 日常生活琐事 | 做饭、购物、起居、小意外 |
| `media` | 游戏与二次元 | 游戏、番剧、角色、账号、社区 |
| `creation` | 创作与写作 | 写作、剧情规划、翻译 |
| `society` | 社会观察与评论 | 政策、道德、战争、垄断、公平 |
| `knowledge` | 知识追问 | 物理、科学、哲学问题 |
| `dream` | 梦境 | 梦的内容与体验 |

**`unknown` 单独一类**：确实无法归入以上任何一类时使用。

### 2.3 类别的来源

**不是拍脑袋定的。** 做法是：把 192 条主题全部读一遍，按语义人工归并，找出反复出现的主题族。

**归并过程中发现的问题**：192 条主题里，**没有两条是完全相同的**——这本身就证明了 v1 的 `topic.primary` 是「描述」而不是「分类」。

### 2.4 ⚠️ 覆盖率测试的局限

做了一次关键词粗映射，结果是 `unknown 34/192 = 18%`。

**但这个 18% 不能当成分类体系失败。** 原因：

1. **关键词映射正是 Task 09 证伪过的方法**（只有 20% 与模型一致）
2. 我抽查了未命中的 10 条，**它们都能归入 12 类中的某一类**，只是我的关键词表没覆盖到：

| 未命中主题 | 应归类 |
|---|---|
| 家中再次出现蛐蛐及其原因 | `daily` |
| 雨夜半夜醒来 | `body` |
| 错过某事，因上班而遗忘 | `work_money` |
| 期待或催促某事物出现 | `desire` |
| 温度设置与怕冷偏好 | `body` |
| 鲨鱼奶的味道 | `daily` |

**所以 18% 是关键词表的缺陷，不是类别的缺陷。**

**真实覆盖率要等模型跑过才知道。** 这一点写在这里，避免下次把 18% 当结论。

## 三、P0-B：情绪枚举重构

### 3.1 先诊断 `other`

**87 次 `other` 里，只有 13 次是「除了 other 没有别的标签」。**

| 情况 | 次数 |
|---|---|
| 只有 `other` | 13 |
| `other` + 其他标签 | 74 |

**共现对象**：frustration 36、confusion 18、joy 12、sadness 10、hope 6……

**结论：`other` 被当成「还有个说不出的第二情绪」在用，不是「我分类不出来」。**

**而「分类不出来」已经有 `unknown` 了。两个值语义重叠，这是 v1 的设计错误。**

### 3.2 v2 的处理

```
❌ 删除 other
✅ 保留 unknown 作为唯一「无法命名」的值
✅ 新增 7 个标签
```

### 3.3 新增的 7 个标签及证据

**依据：13 条「只标 other」记录的 `quoted_cues`。**

| 新标签 | 证据线索 | 出现次数 |
|---|---|---|
| `disgust` | 「恶心死了」 | 1 |
| `self_deprecation` | 「明明我会做菜…因为我懒」×2 | 2 |
| `irony` | 登月阴谋论反转段子 | 1 |
| `playfulness` | 「有点意思」「又要爆炸」「可惜不能」 | 2 |
| `anticipation` | 「迫不及待了」「快端上来吧」 | 1 |
| `affection` | 「想和🌸妹贴贴」 | 1 |
| `admiration` | 「制作组是真的厉害」 | 1 |
| `helplessness` | 「晕3D比晕车严重得多」 | 1 |

**最终枚举（23 个）：**

```
v1 原有（14）: joy sadness anger fear anxiety loneliness
              fatigue relief gratitude nostalgia frustration
              numbness confusion hope
v2 新增（8）:  disgust self_deprecation irony anticipation
              affection admiration helplessness playfulness
兜底（1）:     unknown
```

### 3.4 ⚠️ 这个扩容是假设，不是结论

**必须说清楚：**

```
样本量        13 条
推断方法      我（模型）读 quoted_cues 后判断
验证状态      未验证
```

**这正是 GPT 提醒的那条原则要防的事——「模型推测不能冒充真实偏好」。**

**所以在 schema 里加了 `_provisional` 字段：**

```json
"_provisional": {
  "emotion_enum": true,
  "note": "新增标签依据 13 条样本推断，样本过小"
}
```

**使用方必须把新增的 8 个标签当作待验证，而不是既定分类。**

**真正的验证方式**：用 v2 跑一遍，看 `unknown` 占比能否从 26.5% 降下来，同时不出现新的「标签泛滥」。
如果 `unknown` 降了但某个新标签滥用（比如 `playfulness` 占 30%），说明这 8 个也定错了。

## 四、P1：`interpretation` 改为必填

v1 有 2 条记录**完全没有这个字段**（对象本身缺失，不是值为 null）。

v2 把它加入 `required`，并允许全 null：

```json
"interpretation": {"text": null, "kind": "none"}
```

**「没有解释」是一个合法结果；「字段不存在」不是。**

## 五、v2 其他改动

| 改动 | 原因 |
|---|---|
| 新增 `schema_version: "2.0.0"`（必填） | 同一份数据文件里会有 v1/v2 混存，必须能区分 |
| 新增 `_provisional` | 把假设和结论分开记录 |
| 新增条件校验：`category=unknown` 时 `secondary` 必须为空 | 防止自相矛盾 |
| `detail` 上限 40 字 | 防止又写成小作文 |

## 六、迁移方案

### 6.1 不重跑的部分

**v1 的 223 条结果保留，不删除、不覆盖。**

它们仍然是「关键词法不可靠」这个结论的原始证据（`docs/18`）。

### 6.2 重跑方式

```
输出文件        local/text_analysis.v2.jsonl（新文件，不覆盖 v1）
批次清单        复用 local/text_batch_manifest.csv（223 条已定位）
processed 标记  重置为 0（v2 独立计数）
```

### 6.3 成本预估

```
v1 实测        223 条 → ¥0.4238 → 约 ¥0.0019/条
v2 预计        结构略复杂（多一个 category 字段），token 约 +8%
               223 × 0.0019 × 1.08 ≈ ¥0.46
```

**预算 ¥16.58，够跑 30 多次。但按 GPT 的 P0→P1→P2 顺序，先验证 schema 再全量。**

### 6.4 建议：先跑 20 条验证

```
先跑 B001 + B002（20 条）       约 ¥0.04
检查四件事：
  ① unknown 占比是否从 26.5% 下降
  ② 新标签有没有被滥用（单个标签 > 30%）
  ③ category 分布是否合理（不该全挤在一类）
  ④ detail 长度是否都在 40 字内
通过 → 再跑全量
不通过 → 改 schema，不花钱重跑全量
```

**这是避免「花 ¥0.46 再发现一次 schema 错」的唯一办法。**
