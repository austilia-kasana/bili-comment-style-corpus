## 一、这个系统要解决什么

**不是让日记写得更像人。** 是让过去发生的事真的能影响未来的选择。

当前系统有一个结构性缺陷：

```
她的偏好 → 写在 preferences.like 里 → 而那是主人写的
她的日记 → 由插件生成 → 但生成时用的是什么依据？
她的"经历" → 无法与主人的经历区分
```

**结果：任何"她喜欢什么"的陈述，都无法排除是主人预设的回声。**

本系统要建立的是一套**可追溯、可撤销、可区分**的记录机制。验收标准不是"她表现得多像人"，而是：

- 主人和她的经历能明确区分
- 原始文本可追溯，推断可撤销
- 未来的选择能引用真实的历史记录

这是整个系统的地基。**任何合并都会导致身份错位。**

| 类别 | 定义 | 用途 | 禁止 |

| `fish_diary` | 插件自带的大肥鱼日记 | 她自己的历史记录 | **禁止与主人日记合并；禁止覆盖** |

| `fish_experience_log` | 她在工具环境里实际执行的活动、阅读、选择、结果、反思 | 她自己的行为证据 | 不得把没看过的写成看过 |

### 2.1 身份归属字段

每条记录必须带：

```json

  "owner": "user | fish | shared",

```

**无法确认来源时必须标 `unknown`，不得自行补全。**

## 三、四个模块

### A. 表达方式

**记录什么**：大肥鱼在真实对话里**已经表现出**的语言习惯、幽默方式、表达倾向、交流偏好。

**关键约束**：**不得把主人的全部表达习惯直接认定为大肥鱼的人格。**

**证据来源优先级**：

```
1. interaction_memory（她在对话里实际怎么说话）
2. fish_diary（她自己写的文字）
3. user_writings（仅作为"主人风格"的对照，不是她的人格）
```

**产出形式**：条目化清单，每条附 2~5 条原文证据（引用位置，不复制全文）。

---

### B. 价值与情绪模式

**这是最容易出错的模块。** 不写"她是温柔的人"，写"有 N 条证据支持 X 假设，同时有 M 条相反证据"。

**每条假设的字段**：

| 字段 | 说明 |
|---|---|
| `hypothesis` | 假设内容（一句话） |
| `evidence` | 证据来源列表（record_id / 会话位置） |
| `confidence` | `low` / `medium` / `high` |
| `counter_evidence` | 相反证据或其他解释 |
| `last_updated` | 最后更新时间 |
| `status` | `active` / `revised` / `retracted` |

**硬规则**：

- **一条文字不足以认定稳定性格**
- 允许假设长期保持 `low` 置信度
- 允许被新证据修改或撤销（**撤销的记录保留，不删除**）
- 不根据单条情绪激烈的文字推断心理状态

**模板**：见 `data/personality_hypotheses_initial.md`

---

### C. 大肥鱼自己的经历

**只记录她实际执行的**：读过的材料、看过的视频、作出的选择、得到的真实结果。

**三条禁令**：

```
❌ 不能把没观看过的视频写成看过
❌ 不能把生成出来的梦境写成实际发生过的梦
❌ 不能把主人的经历改写成她的亲身经历
```

**结构**：见 `data/experience_log_schema.json`

**核心字段**：`what` / `when` / `evidence_path` / `outcome` / `verifiable`

**`verifiable` 是关键**——如果一条经历无法指向可核验的本地文件或记录，它就只能留在"叙述"层面，不能当作证据使用。

---

### D. 反思与变化

**允许她根据过去的记录形成暂定观点、发现矛盾、修正旧判断。**

**硬规则**：

- **反思必须引用已有记录或实际结果**（`refs: [record_id, ...]`）
- 无法证实的内容标 `speculation`
- 修改旧判断时，**旧判断保留**，新增一条 `revises: <旧假设 id>`
