## 三、最重要的发现：关键词启发式是错的

Task 07 用纯关键词给 224 条打了粗判。这次用模型重跑，两边都有的 80 条可以对比：

```
完全一致        16 / 80 = 20.0%
```

**交叉表里最刺眼的一行：**

| 启发式判定 | 模型判定 | 条数 |
|---|---|---|
| neutral | negative | **26** |
| neutral | mixed | 14 |
| negative | negative | 13 |

**启发式说「没什么情绪」的 26 条，模型判定为负面。**

**这不是模型过度解读，而是关键词法的结构性缺陷：** 它只认情绪词，而人的负面表达大量依赖语气、省略、反讽、以及「平静地叙述一件坏事」。

**Task 07 当时的结论是「valence: neutral 183 / negative 21」。** 这次模型给出的是「negative 96 / neutral 12」。**两个分布几乎相反。**

**真实分布更接近模型这一版**——因为 Task 07 也已经指出过，关键词法对短文本不敏感（206/224 落在 low 置信度）。

## 四、三个暴露出来的问题

### 4.1 主题无法聚合

**192 条有主题，但前 20 高频主题的频次全是 1。**

原因：schema 里 `topic.primary` 是自由字符串，模型给的是**高度具体的描述**（如「骑手超时送泳衣导致当天没游成泳」），而不是**可聚合的类别**。

**结果：主题字段可用来看单条，不能用来做统计。**

**修法**：下一版 schema 应该分两层——`category`（固定枚举，如 生活/情绪/游戏/工作/人物）+ `detail`（自由描述）。

### 4.2 `other` 标签泛滥

**87 次 `other` 说明枚举设计有问题。** 当前 16 个标签覆盖不了实际表达。

**修法**：先跑一批开放式标签，聚类后再定枚举，而不是先定枚举再硬塞。

### 4.3 两条记录缺 `interpretation`

```
解释类型: {'restatement': 30, 'none': 59, 'inference': 132, None: 2}
```

**2 条记录缺这个字段**——模型漏输出了。**需要用 schema 校验补齐。**
